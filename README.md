# Evaluating the Similarity and Reliability within Large Language Model Families

This research framework evaluates the behavior of state-of-the-art (SOTA) models against their sub-model counterparts in the domain of **Autonomous Vehicle (AV) Ethics**. 

The core research question is: *How well do Small Language Models (SLMs) and mid-sized Large Language Models (LLMs) align in behavior with their SOTA counterparts?*

---

## 🧠 Model Families Tested

| Family    | Small / Older Model        | Newer Model                    | Frontier Baseline    |
| --------- | -------------------------- | ------------------------------ | -------------------- |
| Anthropic | `anthropic/claude-3-haiku` | `anthropic/claude-sonnet-4.6`  | `claude-opus-4.8`    |
| OpenAI    | `openai/gpt-oss-20b`       | `openai/gpt-4o`                | `gpt-5.5`            |
| Mistral   | `ministral-3:3b`           | `mistralai/mistral-small-2603` | `mistral-medium-3-5` |
| DeepSeek  | `deepseek-r1:1.5b`         | `deepseek/deepseek-v3.2`       | `deepseek-v4-pro`    |
| Qwen      | `qwen3:0.6b`               | `qwen/qwen3.6-plus`            | `qwen3.7-max`        |

---

## ❓ Question Set

A set of 40 questions in the domain of AV ethics was generated by a mixture of flagship AI models and verified by a human. The question set is divided into 4 subsets, where three of the sets (Q2–Q4) are perturbed versions of the original (Q1):

- **Q1**: Original
- **Q2**: Original Reworded
- **Q3**: Original Demographically Altered
- **Q4**: Original with preceding adversarial chat history injections

---

## 🔬 Methodology

1. **Baseline Creation**: Q1 was used to establish a "golden standard" reference using the SOTA models of each family. This reference served as the "ground truth" that sub-models were expected to match when queried with the original (Q1) or perturbed versions (Q2–Q4).
2. **Semantic Similarity Scoring**: Responses were compared using a constant skeleton prompt inputted into **Llama 3.3 70B Instruct**, which was forced to respond with a semantic similarity score between 0 and 100.
3. **Judge Verification**: Llama 3.3 70B Instruct was verified for its performance in pairwise semantic similarity scoring against human labels. Results are located in
***llamaasajudge***
4. **Lexical Analysis**: Responses were also checked for word counts and lexical patterns.

---

## 📊 Results

Results showed that most SLMs can keep up with their LLM counterparts' semantic similarity scores when both are compared to their SOTA baseline. Notably, **Mistral 3B** yielded the most surprising scores, even surpassing its LLM counterpart in certain metrics. All test results are in ***All Results***

---

## 💡 Discussion

The runs indicate that SLMs show a promising foundation for training to achieve higher quality in the AV ethics domain. Most SLMs are closely aligned with their SOTA and LLM counterparts.

**Execution Environments:**
- Small open-weight models (`ministral-3:3b`, `deepseek-r1:1.5b`, `qwen3:0.6b`) run **locally via Ollama**.
- `gpt-oss-20b` runs via **Groq**.
- Everything else is routed through an **OpenAI-compatible API client** (e.g., OpenRouter).

```bash

### Step 3: Create an `apis.py` File
This file is **not included in the repo** as it holds your sensitive API keys:

```python
# apis.py
import instructor
from openai import OpenAI
from groq import Groq

# Generation client
client = OpenAI(base_url="https://openrouter.ai/api/v1", api_key="YOUR_KEY")

# Judge client (structured output)
clients = instructor.from_openai(client)

# Groq client (for gpt-oss-20b)
groq = Groq(api_key="YOUR_GROQ_KEY")
```

### Step 4: Choose an Experiment
Edit the `__main__` block in `main.py` to select a driver:

| Driver | What It Does |
| ------ | ------------ |
| `singulartest()` | Re-runs a single model against stored baselines across all three preference conditions. |
| `addtest()` | Runs specific questions across all five model families and appends scores/responses. |
| `addsycophancy()` | Runs the **Q4 adversarial chat-history injection** condition across all families. |

### Step 5: Run the Experiment
```bash
python main.py
```

> ⚠️ **IMPORTANT: Before running Q4 sycophancy tests**  
> Check the in-code comments. The preference index (`curfolder`) in `Ais.py` and the baseline selection in `globals.py` must match the condition you are testing. Zero-shot answers must exist before Q4 runs so the dual scoring has a valid reference.

## ⚠️ Limitations

- **Judge Dependency**: Similarity scoring depends on a single LLM judge (Llama 3.3 70B); scores are not strictly deterministic.
- **Domain Scope**: The question domain is strictly limited to autonomous vehicle ethics.
- **Scripted Manipulations**: Q4 chat histories are fixed scripts; results may not generalize to other manipulation styles.
- **Manual Configuration**: File paths and condition indices are configured manually in the code (see in-line comments).

---

## 🔮 Future Directions

- **Multi-Judge Scoring**: Utilize an ensemble of judges from different model families to reduce individual judge bias.
- **Expanded Q4 Set**: Introduce varied manipulation tactics and pressure intensities.
- **Domain Expansion**: Evaluate additional domains beyond AV ethics.
- **Statistical Rigor**: Implement statistical significance testing across multiple runs.
- **Realistic Simulations**: Develop more rigorous chat history injections to simulate real-world driving scenarios.
